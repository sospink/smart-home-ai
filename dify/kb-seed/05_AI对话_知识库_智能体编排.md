# AI 对话、知识库与智能体编排

## AI 对话链路
平台的聊天主链路由后端代理 Dify 完成。

核心特点：

- 前端调用后端 `/api/v1/chat/completions`
- 后端调用 Dify Chatflow API
- 返回形式是 SSE 流式输出
- 支持会话列表、历史消息、删除会话、停止响应

这意味着：

- 只要 Dify 正常，聊天主功能就能工作
- 即使 Ollama 没部署，只要 Dify 使用其他模型供应商，聊天也能继续

## 知识库链路
知识库管理不是项目自建向量库，而是后端代理 Dify Dataset API。

当前支持：

- 查看知识库列表
- 创建知识库
- 删除知识库
- 查看文档列表
- 通过文本创建文档
- 通过文件上传文档
- 删除文档
- 语义召回测试（hit-testing）

## Dify 在本项目中的角色

### 1. 智能体编排
- 承担 Chatflow / Workflow 编排
- 负责把用户问题路由到不同能力流程

### 2. 对话能力
- 负责多轮会话和回答生成

### 3. 知识库能力
- 负责文档索引、切片、检索与召回

## 知识库文档应该覆盖哪些内容
为了让 Dify 更好回答平台问题，建议知识库优先覆盖：

- 平台总体介绍
- 系统架构与服务关系
- 页面说明与模块边界
- 设备控制与实体映射
- API 能力清单
- 部署与配置说明
- 常见故障与 FAQ

## 常见误解

### 误解 1：聊天直接调用 Ollama
不对。当前主链路是前端 -> FastAPI -> Dify。Ollama 主要用于模型管理和本地模型服务。

### 误解 2：知识库是后端自己的数据库
不对。知识库检索与文档管理目前走的是 Dify Dataset API。

### 误解 3：设备控制直接由前端控制 HA
不对。控制动作主要经过 FastAPI 后端，由后端调用 Home Assistant REST API。
