# 系统架构与服务关系

## 总体架构
系统采用“前端 + 后端 BFF + 外部业务服务”的分层方式：

1. 用户通过 Next.js 前端访问平台页面
2. 前端统一调用 FastAPI 后端
3. 后端再代理或聚合外部服务能力
4. 外部服务包括 Dify、Home Assistant、Ollama、MySQL、可选的 InfluxDB

## 服务职责划分

### Next.js 前端
- 提供用户端和管理端页面
- 登录后通过 JWT 调用后端接口
- AI 对话页消费后端转发的 SSE 流
- 设备页、知识库页、模型页、监控页都直接依赖后端 API

### FastAPI 后端
- 统一认证、鉴权、会话、日志、配置管理
- 作为 BFF 聚合多个服务
- 不直接做大模型推理，而是调用 Dify 或 Ollama
- 对前端暴露统一 API，前缀为 `/api/v1`

### Dify
- 提供 Chatflow / Workflow 智能体能力
- 提供 Dataset 知识库能力
- AI 对话主链路实际走 Dify
- 知识库模块实际也是走 Dify Dataset API

### Home Assistant
- 提供设备状态与控制能力
- 后端通过 REST API 查询实体状态、执行服务调用
- 逻辑设备是后端在多个 HA 实体之上做的聚合抽象

### Ollama
- 负责本地模型管理与本地推理
- 主要用于模型列表、模型状态、模型拉取、模型版本和系统监控相关能力
- 如果没有部署 Ollama，聊天主链路仍可继续使用 Dify，但模型管理模块会显示离线

### MySQL
- 存储 Web 平台自己的业务数据
- 包括用户、操作日志、系统配置等
- 不承载 Dify 自己的内部数据库

## 当前数据流

### AI 对话
用户输入 -> 前端 `/chat` -> 后端 `/api/v1/chat/completions` -> Dify Chatflow -> SSE 返回前端

### 知识库管理
管理端页面 -> 后端 `/api/v1/knowledge/...` -> Dify Dataset API

### 设备控制
用户或工作流 -> 后端 `/api/v1/devices/...` -> Home Assistant REST API -> 返回最新状态

### 系统监控
前端监控页 -> 后端 `/api/v1/monitor/...` -> 聚合 MySQL / Dify / HA / Ollama / 系统资源信息

## 关键边界

- 聊天主链路依赖 Dify，而不是直接依赖 Ollama
- 设备控制依赖 Home Assistant 在线
- 知识库问答效果依赖 Dify Dataset 中是否已有文档
- InfluxDB 目前是预留配置，不是系统主链路必需项
