# 部署配置与运行边界

## 最小运行依赖
要让平台主体可用，至少需要以下服务：

- Next.js 前端
- FastAPI 后端
- MySQL
- Dify

如果还要设备控制，则需要：

- Home Assistant

如果还要本地模型管理，则需要：

- Ollama

## 服务是否必需

### 必需
- FastAPI：核心业务入口
- Next.js：页面入口
- MySQL：业务数据存储
- Dify：聊天和知识库主链路

### 按需
- Home Assistant：设备控制与状态查询
- Ollama：本地模型服务与模型管理
- InfluxDB：可选时序数据服务，目前不是主链路硬依赖

## 关键配置项

### 数据库
- `DATABASE_URL`

### 认证
- `SECRET_KEY`
- `ALGORITHM`
- `ACCESS_TOKEN_EXPIRE_MINUTES`

### Dify
- `DIFY_BASE_URL`
- `DIFY_API_KEY`
- `DIFY_DATASET_API_KEY`

### Home Assistant
- `HA_BASE_URL`
- `HA_TOKEN`

### Ollama
- `OLLAMA_BASE_URL`

### InfluxDB
- `INFLUXDB_URL`
- `INFLUXDB_TOKEN`
- `INFLUXDB_ORG`
- `INFLUXDB_BUCKET`

### 其他
- `AGENT_API_KEY`
- `CORS_ORIGINS`

## 云服务器部署边界

当前项目可以采用两种思路：

### 1. Docker Compose 部署
- 更统一
- 更适合整套服务一起编排
- 更新通常需要重建镜像

### 2. 宿主机部署
- 前端、后端直接跑在系统服务里
- MySQL、Nginx 直接使用系统服务
- 更新更直观

## 当前项目的一个现实特点
聊天主链路依赖 Dify，因此在云服务器内存不足以部署 Ollama 的情况下，仍然可以运行平台主体。

此时会受到影响的主要是：

- 模型管理页
- Ollama 健康状态
- 本地模型拉取与本地模型列表

不一定会受到影响的主要是：

- AI 对话
- 知识库问答
- 用户管理
- 监控大屏的大部分能力
