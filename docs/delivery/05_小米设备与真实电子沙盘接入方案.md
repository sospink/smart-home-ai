# 小米设备与真实电子沙盘接入方案

> **项目：** 基于智慧家居场景的大语言模型智能体科研应用一体机  
> **更新日期：** 2026-05-17  
> **定位：** 后期硬件接入策略与前置依赖清单  
> **结论：** 平台不直接对接小米云，统一通过 Home Assistant 抽象设备；真实电子沙盘等待线下硬件协议确认后重写适配。

---

## 一、总体接入架构

```text
用户 / 验收专家
  -> Web 管理平台
  -> FastAPI 后端统一接口
  -> Home Assistant
  -> 小米设备 / Matter 设备 / Zigbee 设备 / 真实电子沙盘适配器

AI 对话
  -> Dify Chatflow
  -> Dify HTTP 节点
  -> FastAPI 后端统一接口
  -> Home Assistant / 真实沙盘适配层
```

核心原则：

- 平台只维护统一设备接口，不在业务代码中绑定具体小米云协议。
- HA 负责吸纳小米、Matter、Zigbee、MQTT 等设备。
- Dify 只调用后端接口，不直接持有 HA Token 或小米账号。
- 真实电子沙盘不以当前虚拟沙盘为最终方案，后续按硬件协议重写。

## 二、小米设备接入路线

| 路线 | 适用场景 | 优点 | 风险 | 验收定位 |
|---|---|---|---|---|
| Matter / Thread / Wi-Fi 本地接入 | 支持 Matter 的小米或生态设备 | 本地化能力强，适合断网验收 | 设备型号受限 | 核心验收优先 |
| 小米官方 `ha_xiaomi_home` | 米家生态设备较多 | 覆盖面广，官方维护 | 部分设备可能走小米云，本地模式依赖中枢网关或设备能力 | 核心/扩展视设备而定 |
| HA 官方 `xiaomi_miio` | 空净、插座、网关等受支持设备 | HA 官方文档支持 | 支持面较窄，部分设备需 token | 可作为局部接入 |
| Zigbee/MQTT/网关 | Zigbee 子设备或可刷/可桥接设备 | 本地化强 | 需要网关/协调器和配置 | 核心验收可选 |
| 第三方 `hass-xiaomi-miot` | 官方接入不足时兜底 | 设备覆盖较广 | 第三方维护、版本风险 | 扩展或兜底 |

参考：

- Home Assistant Xiaomi Home / `xiaomi_miio`：https://www.home-assistant.io/integrations/xiaomi_miio/
- Home Assistant Matter：https://www.home-assistant.io/integrations/matter/
- 小米官方 HA 集成： https://github.com/XiaoMi/ha_xiaomi_home
- 第三方 Xiaomi MIoT： https://github.com/al-one/hass-xiaomi-miot

## 三、离线验收策略

合同强调本地化部署，因此后期验收应区分：

| 类型 | 是否作为断网核心证据 | 说明 |
|---|---|---|
| Ollama 本地模型 | 是 | 必须本地可用 |
| Dify 本地 Chatflow/Workflow | 是 | 不应依赖公网固定地址 |
| Dify 本地知识库检索 | 是 | dataset 和向量检索应本地可用 |
| HA 本地可控设备 | 是 | Matter、局域网、网关本地设备优先 |
| 小米云依赖设备 | 否 | 可作为联网扩展演示，但不能作为断网核心证据 |
| 当前 HA 虚拟沙盘 | 临时兜底 | 可在真实沙盘未到场时演示流程 |
| 真实电子沙盘 | 交付核心 | 需硬件协议确认后验收 |

## 七、真实沙盘硬件方问题清单

目前真实线下沙盘细节未知，因此正式实现前必须向甲方或硬件方确认：

| 类别 | 问题 |
|---|---|
| 基础信息 | 沙盘厂家、型号、控制器型号、是否已有上位机软件、联调负责人、预计到场时间 |

| 命令表 | 每类设备的控制命令、参数类型、取值范围、幂等性、成功/失败返回格式 |
| 状态回传 | 是否能查询全量状态，字段名、单位、刷新频率、时间戳格式、状态变化延迟 |

| 事件推送 | 是否支持主动推送状态变化，推送协议、订阅方式、断线重连方式；若不支持，确认轮询周期 |

| 联调资料 | 协议文档、Postman、SDK、模拟器、测试账号、样例数据、测试环境地址 |

## 八、真实沙盘适配方向

正式沙盘到场后建议采用适配器模式：

```text
前端 `/sandbox`
  -> 后端 `/api/v1/sandbox/*`
  -> SandboxAdapter
      -> HaVirtualSandboxAdapter（当前虚拟兜底）
      -> RealHardwareSandboxAdapter（真实沙盘）
```

后续实现要求：

- 前端页面按真实沙盘点位重新设计。
- 后端保留统一 `/sandbox` API，不让前端直接调用硬件协议。
- 真实沙盘适配层负责协议转换、鉴权、状态回读和错误处理。
- 真实硬件不可用时，可切换到 HA 虚拟沙盘兜底演示。

## 十、当前结论

1. 小米智能家居后期可通过 HA 接入，但是否满足离线核心验收取决于具体设备。
