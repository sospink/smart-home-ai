# 后期开发任务执行手册

> **项目：** 基于智慧家居场景的大语言模型智能体科研应用一体机  
> **更新日期：** 2026-04-27  
> **文档定位：** 后期阶段开发任务的统一执行流程、提示词模板和 Todo 同步规则  
> **适用对象：** 后续 AI 代理、开发人员、项目管理人员  

---

## 一、执行总原则

1. **禁止无边界全量开发**：不能让 AI 一次性“把所有后期功能都做完”。每次只执行一个阶段、一个批次、一个页面或一个模块。
2. **先读文档，再写代码**：每次开发前必须读取本手册、阶段计划、进度日志、页面台账和完整性标准。
3. **先审计当前实现，再拆 Todo**：不能凭文档直接改代码，必须先看当前页面、后端接口、Dify DSL、HA/Ollama/知识库配置的真实状态。
4. **先处理 P0/P1 风险**：真实凭证、Dify 公网地址、Token 暴露、Mock 数据、RAG 未绑定等风险优先级高于普通页面优化。
5. **硬件未知就标阻塞**：小米设备、真实电子沙盘、线下点位、协议和账号未确认时，只能写清阻塞和适配预留，不能包装成已完成。
6. **页面存在不等于功能完成**：菜单、卡片、列表、新增按钮、跳转入口都不能单独计为交付完成。
7. **完成后必须同步文档**：代码完成后同步更新 `03_开发进度日志.md` 和相关台账；页面闭环任务同步 `07_前端页面闭环整改台账.md`。

## 三、标准任务输入模板

后续可以直接复制以下模板派发任务：

```text
请执行后期交付第 X 阶段 / 第 X 批任务。

范围：
- 页面/模块：
- 相关文档：
- 不允许修改的范围：

依据：
- docs/delivery/02_后期交付阶段开发计划.md
- docs/delivery/03_开发进度日志.md
- docs/delivery/06_功能模块完整性评审清单.md
- docs/delivery/07_前端页面闭环整改台账.md
- 如涉及硬件，补充 docs/delivery/05_小米设备与真实电子沙盘接入方案.md

要求：
1. 先 review 当前代码、后端接口、Dify/HA/Ollama/知识库相关实现。
2. 生成本轮 Todo，并按“待做 / 进行中 / 已完成 / 阻塞 / 待验证”维护。
3. 只修改本轮范围内文件，不做无关重构。
4. 实现后运行必要验证。
5. 完成后同步更新 03 进度日志和相关台账。
6. 最终说明完成内容、验证结果、文档同步、剩余阻塞和下一步建议。
```

页面闭环任务可使用更具体模板：

```text
请执行 07 台账中的页面闭环整改。

范围：
- 页面：
- 批次：
- 优先级：

目标：
- 补齐页面操作闭环、后端接口闭环、外部系统证据、异常状态和验收说明。

要求：
1. 先读取该页面源码、相关组件、API 封装和后端路由。
2. 列出当前已具备能力和缺口。
3. 按 06 的完整性标准实现本轮范围。
4. 验证页面构建、核心操作和错误态。
5. 更新 03 和 07。
```

## 四、AI 标准执行流程

每次任务按以下流程执行：

| 步骤 | 动作 | 输出 |
|---|---|---|
| 1 | 读取文档 | 明确阶段、范围、状态、阻塞、验收口径 |
| 2 | 确认边界 | 明确本轮要做和不做的内容 |
| 3 | 代码审计 | 找到页面、组件、API、后端路由、外部系统调用点 |
| 4 | 建立 Todo | 把任务拆成可执行项，并标注状态 |
| 5 | 实现修改 | 只改本轮范围，遵守项目风格和硬规则 |
| 6 | 自测验证 | 运行构建、语法检查、接口测试或页面验证 |
| 7 | 同步文档 | 更新 `03`、`07`，必要时更新 `04`、`06` |
| 8 | 输出报告 | 说明完成内容、验证结果、剩余风险、下一步 |

## 五、阶段执行规则

### 阶段 1：安全与配置收口

**目标：** 先解除交付 P0/P1 安全风险。

优先 Todo：

| Todo | 优先级 | 验收标准 |
|---|---|---|
| 移除仓库内真实数据库、HA、Dify、Dataset、Agent Key | P0 | 跟踪文件只保留占位值或示例配置 |
| 轮换已暴露密钥 | P0 | 有轮换记录和新配置验证结果 |
| Dify DSL 去公网地址和明文 App Key | P0 | DSL 模板只保留占位符和导入后配置说明 |
| `/sandbox/client-config` 不再向浏览器返回 HA Token | P1 | 前端只调用后端代理接口，HA Token 仅由后端保管 |
| 更新运行时配置说明 | P1 | 系统设置、环境变量、兜底配置优先级清晰 |

完成后同步：

- `03_开发进度日志.md`：更新安全阻塞状态。
- `01_深度审核与真实完成度评估.md`：如风险解除，更新风险状态。
- 部署/运维文档：如配置来源变化，补充说明。

### 阶段 2：Dify 真实链路

**目标：** 证明智能体不是页面演示，而是真实调用设备、数据、知识库和系统接口。

优先 Todo：

| Todo | 优先级 | 验收标准 |
|---|---|---|
| 主 Chatflow 调用本地后端标准接口 | P0 | 无公网固定地址，能在本地部署链路运行 |
| 设备控制 Workflow 调用后端 `/devices` 并回读 HA 状态 | P0 | 对话控制设备后，HA 状态变化 |
| 数据查询 Workflow 去 Mock，调用真实传感器/历史接口 | P1 | 回答中能标明真实数据来源 |
| RAG Workflow 绑定真实 dataset | P1 | 有 dataset ID、命中文档片段和回答证据 |
| 平台 Agent 实例可触发 Dify 测试运行 | P1 | `/agents` 页面可看到运行结果或 workflow_run_id |

完成后同步：

- `03_开发进度日志.md`：更新 Dify 主链路、设备控制、数据查询、RAG、Agent 实例状态。
- `04_验收专家操作指引.md`：补专家可执行步骤。
- `07_前端页面闭环整改台账.md`：如涉及 `/agents`、`/chat`，更新对应页面状态。

### 阶段 3：小米 / HA / 真实沙盘硬件确认

**目标：** 把硬件不确定项变成清单、矩阵和阻塞状态。

优先 Todo：

| Todo | 优先级 | 验收标准 |
|---|---|---|
| 获取小米设备型号和接入方式 | P0 | 完成设备兼容矩阵 |
| 确认设备是否支持本地控制 | P0 | 标明 Matter、本地网关、局域网、云端依赖 |
| 建立 HA entity 映射表 | P1 | 平台设备与 HA entity 一一对应 |
| 获取真实电子沙盘协议、点位、命令、数据格式 | P0 | 未提供前保持硬件阻塞 |
| 明确真实沙盘适配层边界 | P1 | 不复用虚拟沙盘假装最终实现 |

完成后同步：

- `05_小米设备与真实电子沙盘接入方案.md`：更新设备矩阵和沙盘问题清单。
- `03_开发进度日志.md`：更新硬件阻塞状态。
- `07_前端页面闭环整改台账.md`：如影响 `/devices`、`/sandbox`，更新页面状态。

### 阶段 4：前端页面闭环补齐

**目标：** 按 `07` 台账逐页推进，不再以页面存在或卡片存在作为完成标准。

执行批次：

| 批次 | 页面 | 目标 |
|---|---|---|
| 第一批 | `/dify`、`/home-assistant`、`/agents`、`/devices` | 打通 Dify、HA、智能体实例、设备控制核心链 |
| 第二批 | `/dashboard`、`/api-console`、`/monitor`、`/chat` | 补齐专家高频操作页面和证据展示 |
| 第三批 | `/sandbox`、`/knowledge`、`/settings` | 补硬件阻塞说明、RAG 证据、配置安全闭环 |
| 第四批 | `/models`、`/users`、`/docs`、`/help-docs`、`/conversation-records` | 补管理、文档、记录和验收辅助能力 |

每个页面必须检查：

- 入口是否可达，页面是否非占位。
- 主要操作是否能完成。
- 是否有详情、编辑、删除/禁用、执行或测试入口。
- 是否有加载、空态、错误、未配置、无权限、离线和超时状态。
- 是否有日志、运行记录或外部系统状态证据。
- 是否能按合同条款形成专家验收截图。

完成后同步：

- `07_前端页面闭环整改台账.md`：更新完成状态、验收证据和完成记录。
- `03_开发进度日志.md`：更新页面状态。
- `04_验收专家操作指引.md`：必要时补操作步骤。

### 阶段 5：专家验收脚本和证据链

**目标：** 让非技术专家按合同条款逐条验收。

优先 Todo：

| Todo | 优先级 | 验收标准 |
|---|---|---|
| 按合同条款整理页面入口 | P0 | 每条都有页面入口 |
| 按条款补操作步骤和预期现象 | P0 | 专家可以照着操作 |
| 补接口、日志、外部系统证据字段 | P0 | 能证明不是前端静态展示 |
| 标注硬件/外网依赖 | P1 | 小米云、真实沙盘、HA 实体依赖清楚 |
| 准备截图清单 | P1 | 每条验收可留档 |

完成后同步：

- `04_验收专家操作指引.md`：作为最终专家执行手册。
- `03_开发进度日志.md`：更新验收文档状态。

## 六、Todo 维护规则

每次任务开始后，必须建立 Todo，并使用以下状态：

| 状态 | 含义 |
|---|---|
| 待做 | 已确认要做，尚未开始 |
| 进行中 | 当前正在处理，只允许同时有一个主要进行中任务 |
| 已完成 | 已实现并完成必要验证 |
| 阻塞 | 依赖硬件、账号、协议、密钥、外部系统或产品决策 |
| 待验证 | 代码或文档已完成，但目标环境尚未实测 |

Todo 示例：

```text
- [进行中] 读取 /devices 页面、设备 API 和后端 /devices 路由
- [待做] 补设备详情抽屉和 HA entity 映射展示
- [待做] 补控制失败 Toast 和状态回读提示
- [待做] 更新 03 和 07
- [待验证] 在真实 HA 环境验证小米设备状态回读
```

## 七、完成后同步规则

每次代码或文档任务完成后，按影响范围同步：

| 影响范围 | 必须同步 |
|---|---|
| 任意后期开发任务 | `03_开发进度日志.md` |
| 前端页面闭环 | `07_前端页面闭环整改台账.md` |
| 页面/模块完整性标准变化 | `06_功能模块完整性评审清单.md` |
| 专家操作步骤变化 | `04_验收专家操作指引.md` |
| 小米设备或真实沙盘资料变化 | `05_小米设备与真实电子沙盘接入方案.md` |
| 风险解除或新增重大风险 | `01_深度审核与真实完成度评估.md` |
| 阶段范围或批次变化 | `02_后期交付阶段开发计划.md` |

同步时不要只写“已完成”，必须写清：

1. 完成了什么。
2. 验证了什么。
3. 证据在哪里。
4. 是否还有阻塞。
5. 下一步是什么。

```text

- ...

- 更新了 03 ...
- 更新了 07 ...

剩余风险：

- ...

当前处理：
- 已在 03 标记为阻塞，并在 05/07 保留待确认项。
```

## 九、禁止事项

- 禁止一次性执行所有阶段。
- 禁止在真实硬件未知时伪造已完成状态。
- 禁止把 Mock、fallback、静态展示包装成真实能力。
- 禁止把 Dify、HA、Ollama、公网地址、Token 或密钥写死在前端代码和 DSL 模板中。
- 禁止只改页面不补后端接口、日志、异常和验收证据。
- 禁止完成代码后不更新 `03` 和相关台账。

## 十、当前最优先任务建议

如果没有额外指令，后期开发应优先从以下任务开始：

1. **阶段 1：安全与配置收口**
   - 处理真实凭证进入仓库。
   - 处理 Dify DSL 内嵌 App Key 和公网地址。
   - 处理沙盘接口返回 HA Token。
2. **阶段 2：Dify 真实链路**
   - 数据分析 Workflow 去 Mock。
   - RAG Workflow 绑定真实知识库。
3. **阶段 4 第一批页面**
   - `/dify`、`/home-assistant`、`/agents`、`/devices` 页面闭环。

这三个方向是后期交付的关键路径，优先级高于普通 UI 美化。
