# 验收专家操作指引

> **用途：** 供非技术验收专家按合同参数逐条验证  
> **更新日期：** 2026-05-17  
> **说明：** 本文档是阶段 5 专家验收主脚本。历史合同完成度代表代码/方案覆盖，现场验收仍需按本脚本补齐截图、接口、外部系统和阻塞证据。

## 一、验收前准备

| 项目 | 入口 | 验收前确认 |
|---|---|---|
| 平台后台 | `http://[设备IP]:3100` 或部署地址 | 可登录管理员账号 |
| 后端接口文档 | `http://[设备IP]:8000/api/docs` | 可访问接口说明 |
| Dify 平台 | `/dify` 或本地 Dify 地址 | 可查看 Chatflow/Workflow |
| Home Assistant | `/home-assistant` 或 HA 地址 | 可查看设备实体和场景 |
| Code Server | `http://[设备IP]:8443` | 交付环境实际可访问 |
| JupyterLab | `http://[设备IP]:8888` | 交付环境实际可访问 |

## 二、验收记录字段

每条合同参数建议记录以下字段：

| 字段 | 说明 |
|---|---|
| 页面入口 | 专家实际点击的页面 |
| 操作步骤 | 专家按步骤执行的动作 |
| 预期现象 | 页面或设备应出现的变化 |
| 证据接口 | 后端或 Dify 可证明能力的接口/运行记录 |
| 外部系统证据 | HA、Ollama、Dify、真实硬件状态 |
| 是否依赖硬件 | 是否必须真实设备到场 |
| 是否依赖外网 | 是否需要小米云或外部网络 |
| 验收结果 | 通过/不通过/待硬件确认 |

## 三、页面完整性快速检查

专家逐条验收前，先对每个页面做一次快速判断，避免把半成品页面误判为完成：

| 检查项 | 通过标准 | 不通过示例 |
|---|---|---|
| 页面内容 | 页面有真实业务区，不只是说明卡片或跳转按钮 | 只有几个 Card、一个按钮、静态介绍 |
| 主要操作 | 能完成查看、详情、执行或管理流程 | 只有列表和新增，没有详情/编辑/删除/执行反馈 |
| 状态反馈 | 操作后有成功/失败提示，并能刷新看到结果 | 点击后无反馈，或只弹出固定成功文案 |
| 异常处理 | 未配置、无权限、外部服务离线、硬件离线时有明确提示 | 接口报错后页面空白或无解释 |
| 证据链 | 能找到后端接口、Dify/HA/Ollama/知识库/硬件侧证据 | 只有前端展示，没有任何外部系统记录 |

**通过原则：** 页面可访问只是最低条件；合同功能必须能形成完整操作流程和证据链。详细评审按 `06_功能模块完整性评审清单.md` 执行。

高风险页面需额外检查以下闭环，逐页整改状态以 `07_前端页面闭环整改台账.md` 为准：

| 页面 | 专家检查点 |
|---|---|
| `/dify` | 是否显示本地 Dify 地址、连接状态、应用/Workflow 状态，不能只打开公网跳转页 |
| `/home-assistant` | 是否显示 HA 连接状态、实体摘要、服务调用证据，不能只打开 HA 封面入口 |
| `/agents` | 是否能在平台内测试或调用智能体实例，不能只创建/删除实例 |
| `/devices` | 是否有设备详情、状态回读、操作日志和 HA entity 映射，按钮是否真的可用 |
| `/chat` | AI 回复是否有 workflow_run_id、工具调用结果、失败提示；右侧状态区是否真实或明确待接入 |
| `/dashboard` | 近期活动、服务日志、告警和服务状态是否来自真实数据 |
| `/api-console` | 是否能填写参数并发起真实接口调试，是否有响应和错误展示 |
| `/monitor` | 趋势和历史数据是否标注来源，是否能解释 HA History/InfluxDB/fallback |
