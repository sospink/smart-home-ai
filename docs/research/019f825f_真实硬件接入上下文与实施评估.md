## 3. 硬件与网关结论

### 3.1 DMWG03LM

- 网关型号：小米多模网关 2，商品/铭牌型号 `DMWG03LM`，社区内部 model 映射为 `lumi.gateway.mcn001`。
- 它可以承载 Zigbee、BLE、BLE Mesh 子设备，但不等同于小米官方 Home Assistant 文档中的“中枢网关本地模式”。
- 小米官方开放平台不能因为注册开发者账号，就让自研应用遍历并控制账号下所有已购买的米家/Aqara 消费级设备。
- 社区 `XiaomiGateway3`、`mi-home` 等项目证明局域网控制在技术上可行，但依赖网关固件、token/key、Telnet 或 `openmiio_agent`；其中部分依赖许可证不明确，不宜直接打包进商业交付。

### 3.2 当前可落地路径

原会话最终没有让当前平台直接调用 DMWG03LM 私有协议，而是完成了：

```text
真实灯具/子设备
  -> DMWG03LM 或对应接入链路
  -> Home Assistant
  -> 当前平台后端（REST + WebSocket Registry）
  -> 设备台账、控制页面、AI/Dify、时序与审计
```

这个路径的优点是：当前平台只依赖 Home Assistant 的稳定实体和服务契约；小米私有协议、设备配网与网关兼容性由 HA 所在实训系统负责。

## 6. 当前平台源码现状与运行验证

### 6.1 已具备

- `DeviceGateway`：保存 HA 网关地址和独立凭证。
- `ManagedDevice`：平台逻辑设备台账，不再要求设备写死在前端。
- `DeviceEntityMapping`：一台物理设备可映射多个 HA 实体和不同能力角色。
- HA REST：读取状态、调用 service、查询历史。
- HA WebSocket Registry：读取 Entity、Device、Area Registry。
- `/devices/gateways/{id}/sync`：发现 HA 实体并区分真实硬件、Helper、系统/诊断实体。
- `/devices/gateways/{id}/import`：按 `ha_device_id` 聚合导入，同一物理设备多个实体归为同一平台设备。
- `/devices`：网关 CRUD、设备 CRUD、发现、批量导入、手工映射、状态查看和真实控制。
- `/devices/demo-devices`：只清理 `source=seed` 的历史演示台账，不操作 HA 真机。

## 7. 推荐实现方案

### 7.1 事实源和模式

平台设置中增加明确运行模式：

- `simulation`：没有硬件时使用演示数据，但 UI 和日志必须标注模拟。
- `homeassistant`：HA 为设备状态和控制事实源，演示种子不参与默认搜索/统计/AI 控制。
- 不做静默混合。真实模式下 HA 离线应展示明确错误，不能回退成“控制成功”的模拟响应。

### 7.2 设备接入流程

1. 管理员在系统设置或网关管理中配置 HA 地址和长效 Token。
2. 点击“测试连接”，验证 `/api/` 和 Registry 权限。
3. 点击“同步 HA 实体”，读取状态、实体、设备和区域注册表。
4. 默认只展示推荐真实硬件；可切换查看全部实体。
5. 按 HA Device Registry 聚合并批量导入；管理员可把额外实体加入已有设备映射。
6. 给逻辑设备设置名称、位置、能力标签和主能力。
7. 控制前校验映射、访问模式、允许动作和 HA 当前在线状态。
8. 控制后记录真实目标实体、服务、操作者、成功/失败和外部错误。

### 7.3 AI 控制流程

```text
用户自然语言
  -> 平台本地设备意图识别（普通问答仍走 Dify）
  -> /devices/search?name=...
  -> 只返回启用的动态平台设备与映射
  -> 选择逻辑设备 + role + action
  -> /devices/{device_id}/control
  -> 后端解析为 HA domain/service/entity_id
  -> Home Assistant
  -> 真实状态回读 + OperationLog
```

AI 不应自己猜测 `entity_id`，也不能继续依赖 DSL 里写死的客厅灯、卧室灯等实体名称。歧义时应返回候选设备让用户确认。

### 7.4 沙盘

- 沙盘布局是展示层，可保留房间/图层配置。
- 每个沙盘控件必须绑定平台 `device_id + mapping role`，不能绑定代码常量。
- 真实模式下传感器只读；“数据注入”只在 simulation 模式可用。
- 场景应优先执行 HA `scene.*` 或平台保存的动态动作集合。

## 8. 验收标准

1. 配置真实 HA 后可读取 Registry，页面展示真实设备名称、区域、制造商、型号和多个实体。
2. 可从发现结果创建、编辑、删除平台设备；删除平台台账不删除 HA 实体。
3. 灯具开关至少完成一次“页面点击 -> 平台 API -> HA service -> 状态回读”的闭环。
4. AI 至少完成一次“动态搜索 -> 真实设备确认 -> 控制 -> 审计日志”的闭环。
5. HA 离线、Token 无效、实体 unavailable、服务不支持时均显示真实失败，不返回模拟成功。
6. simulation 与 homeassistant 模式有明确标识，统计和日志不能混淆。
7. 沙盘固定实体只用于虚拟模式，不能进入真实设备搜索和控制链路。

## 9. 风险

- 局域网 IP 可能变化，建议在现场 DHCP 中为 HA、主屏和网关绑定固定租约。
- HA 长效 Token 必须保存在服务端，不进入前端、文档、Git 或截图。
- HA Entity Registry 的实体可能因重新接入集成而改名，平台需通过重新同步和映射修复处理。
- DMWG03LM 的非官方本地能力仍有固件和许可证风险；当前平台以 HA 为边界可以隔离这部分风险，但不能把它写成小米官方开放 API。
- 当前硬件实测主要证明灯具链路；窗帘、门锁、人体、门磁、水浸、BLE Mesh 等仍需逐类实机验收。
