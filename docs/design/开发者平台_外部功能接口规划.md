# 开发者平台外部功能接口规划

> 适用产品：基于智慧家居场景的大语言模型智能体科研应用一体机  
> 用途：为“帮助文档和教程”页以及后续“科研接口调试页 / 开发者平台页面”提供信息架构、接口分组和调试能力规划。  
> 目标：让页面名称与合同参数匹配，同时让 UI 能据此设计真正可演示的接口平台。

## 1. 结论先看

当前项目已经具备一套可落地的外部功能接口基础，但“帮助文档和教程”页面更像入口页，还不是完整的开发者平台。  
从合同和现有代码看，后续开发者平台建议至少包含以下 8 类接口能力：

1. 统一的本地模型调用接口
2. 智能体调用外部功能接口
3. 智能家居系统对接能力
4. 虚拟设备系统与电子沙盘系统对接能力
5. 统一的设备数据访问接口
6. 统一的设备控制接口
7. 知识库检索接口
8. 文件与系统接口

其中：

- 现在最适合先做成正式调试页的是：`统一的本地模型调用接口`、`统一的设备数据访问接口`、`统一的设备控制接口`、`知识库检索接口`
- 现在最适合先做说明页、后做深度调试页的是：`智能体调用外部功能接口`、`智能家居系统对接能力`、`虚拟设备系统与电子沙盘系统对接能力`

当前能力已经覆盖：

- 实时状态数据
- 历史数据
- 设备运行信息

- `GET /states/realtime`：平台已纳管设备及 HA 实时状态快照
